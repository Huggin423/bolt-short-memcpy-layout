# 交付核验记录

核验日期为 2026 年 11 月 18 日。环境为 AMD Ryzen AI Max+ 395 主机上的原生 x86-64 Linux（内核 `7.0.0-28-generic`）和 Docker Engine 29.7.2。容器测试使用新建的临时容器、只读根文件系统、可执行的临时目录及断网模式。两次性能复测均绑定逻辑 CPU 14。

| 项目 | 结果 |
| --- | --- |
| PDF 与 Notion | 仓库中的 10 页 PDF 与 Notion 的正文、三张图、数据表、哈希及附录 B 对得上。PDF 把 `rw,exec` 等长参数折行，从 PDF 复制时可能引入换行，优先用 README 的命令。文中的 128 GiB 标为主机配置记录，本次 Linux 报告约 62 GiB 可见内存，两个数采用不同口径，未核验物理配置。 |
| Release 文件与内容 | GitHub Release 公布 80,481,566 字节及 SHA-256。测试使用 AMD 机保留的原始归档，完整 SHA-256 与 GitHub 一致。测试环境未能完整下载 GitHub 附件。加载后确认 `linux/amd64` 镜像和预期 ID，检查了 `/course/bin/llvm-bolt`、`mawk.orig`、两份 profile、AWK 脚本、各输入、复现及审计脚本、原生实验原始记录。 |
| 离线 smoke | 使用本地已校验归档运行 `reproduce.sh smoke`。布局检查、四组输出、零填充预算逐字节回退和运行后 ELF 哈希均通过。 |
| ELF 回归测试 | 对镜像中同一个 `llvm-bolt` 现场编译并运行小型测试。原 ELF 与改写版各完成 514 次带保护页的复制检查。16 字节分界使用无符号比较并保留 libc 长路径。正反例覆盖 10,000 次和 90% 阈值、长度中途改写、32 位窄比较及错 ELF profile。后 3 种情形还验证外部脚本逐字节回退。 |
| 源码检查 | 补丁对 AMD 留存的 LLVM `cbfac21cd384f6c7c480c2d0026ecedfe2d619e7` 源码归档成功执行 `git apply --check`、应用及反向检查。镜像内两份审计脚本与补丁中的脚本仅差新增的 SPDX 注释。此次回归使用已发布的 BOLT，未从头重编译 LLVM。 |

## 容器性能复测

以下为配对墙钟耗时的中位数及 95% 置信区间。两次各测 144 轮 × 4 组，总计各 2,304 条计时，输出哈希与原生参考匹配。第一轮直接运行容器 `bench`，第二轮从 `reproduce.sh bench` 启动。PDF 列出的是此前的原生进程计时。

| 负载 | 第一次 | 第二次 |
| --- | ---: | ---: |
| `heldout` | −0.69% [−0.84%, −0.57%] | −0.69% [−0.82%, −0.52%] |
| `mixed` | −0.14% [−0.27%, −0.03%] | −0.25% [−0.38%, +0.06%] |
| `long` | +0.06% [−0.03%, +0.15%] | +0.07% [−0.11%, +0.21%] |
| `long_alias` | +0.21% [+0.02%, +0.35%] | +0.03% [−0.22%, +0.26%] |

留出词频两轮均缩短。全长别名负载第一轮测到小幅回退，第二轮区间跨 0。现有结果尚无法确认该回退是否跨次稳定出现，也不足以证明不命中短路径时性能必定无回退。两轮都通过长路径地址和机器码检查，因此布局相同仍需配合负载计时验证。
